# バンド定量の追加計画

調査日: 2026-11-08。設計メモ（現行実装に合わせて更新）。実画像・実験情報は使用していない。

**現行スコープ（2026-11-08 更新）**: 固定サイズの矩形ROIで元の16-bitグレースケール画像を測り、結果表とCSV・Excelを出力するところまで。ローディングコントロールによる正規化、基準レーンに対する相対値は次の版に回す。定量を使わない既存の図作成・PPTX・PNG出力は、そのまま完了できる。

## 1. 方針

既存の手順に **`3. 定量(Optional)`** を追加する。定量を開始しなくても、現在の図作成・PPTX・PNG出力はそのまま完了できる。

最初に実装する方式は、**同じ幅・高さの矩形ROI内の画素値を合計し、近傍の背景を差し引く方法**とする。Pythonの既存依存ライブラリだけで実装できる。

- 比較する同じバンドのレーン間では、ROIの幅・高さを必ず揃える。面積が同じだけでは不十分。
- 個別ROIは上下左右への平行移動だけを許可する。個別リサイズ・個別回転は設けない。
- サイズ変更は選択した枠の角・辺のハンドル、または共通の幅・高さ欄から行い、全レーンのバンド・背景ROIに反映する。各枠の中心を厳密に保持し、整数画素を測るため2px刻みとする。画像端に達したら拡大を止める。
- 定量値は元の16-bitグレースケール画像から計算する。表示の明るさ・コントラスト・拡大率を変えても値は変わらない。
- 最初のリリースでは、局所背景補正と、レーン別の結果表・CSV・Excel出力までを提供する。ローディングコントロール補正、相対値は次版にする。

サイズを共有する単位は、原則として「1段の同じ標的を、同じ画像・同じ露光で比較するレーン群」とする。1段に測りたいバンドが2本ある場合に備え、1つの段に複数のグループを持てるようにする（グループIDで区別し、`panel_id` だけを鍵にしない）。別の段やローディングコントロールには別の共通サイズを設定できる。初期値は直前のサイズを引き継げるが、レーンごとの例外は作らない。

## 2. 調査から選ぶ方法

### 採用: 固定矩形の積分強度と局所背景

ImageJの `RawIntDen` はROI内の画素値の総和である。バンドと背景を同じ大きさで測る設計は、この量と対応づけて検証できる。[ImageJ公式: Analyze Menu](https://imagej.net/ij/docs/menus/analyze.html)

公開プロトコルでも、矩形を移動してバンドと近傍の背景を測り、全バンドで矩形サイズを変えない手順が示されている。本計画ではこのROI操作を採用する。同論文の複数露光を用いる回帰解析は初版の対象外とする。[Cañada-García & Arévalo, 2023](https://en.bio-protocol.org/pdf/Bio-protocol4667.pdf)

Pythonでは、`tifffile` で元の画素配列を読み、NumPyで矩形を切り出して総和と平均を計算する。整数の桁あふれ・符号なし整数の減算を避けるため、集計・背景補正は `float64` で行う。[tifffile公式](https://github.com/cgohlke/tifffile)、[NumPy公式: sum](https://numpy.org/doc/stable/reference/generated/numpy.sum.html)

### 後の拡張にする方法

- **レーンプロファイルのピーク面積**: ImageJのGels機能は、レーンの強度プロファイルにベースラインを引いてピーク面積を測る方式。複数バンドやスメアには検討価値があるが、矩形の総和とは別方式として扱う。初版にベースライン編集を増やさない。[ImageJ公式: Gels](https://imagej.net/ij/docs/menus/analyze.html)
- **Rolling-ball背景補正**: scikit-imageに実装がある。ただし半径などの設定と追加依存が必要になる。初版は、人が位置を確認できる局所背景ROIを使う。[scikit-image公式](https://scikit-image.org/docs/stable/auto_examples/segmentation/plot_rolling_ball.html)
- **自動セグメンテーション**: バンドごとに輪郭を変えると測定面積が揃わない。初版では採用せず、将来使う場合も位置の候補提示に限定する。

- `src/wb/ingest.py`: raw16 TIFFを取り込み、解析画像との対応を保存している。ただしraw16も `unverified`。別ファイルの表示画像とraw16の対応は、ファイル名や寸法比の候補であり、座標の一致を保証していない。

- 既存の `add_annotation` API（`src/wb/app.py`）と旧画面 `src/wb/web/annotate/annotate.js` は、`measurement_roi` / `background_roi` を任意の多角形で追加できる。定量グループを持つ段では、この経路で該当purposeを追加・変更できないように拒否する。
- `src/wb/api.py` / `src/wb/app.py` / `src/wb/project.py`: 更新版の照合、保存履歴、元画像のハッシュ確認を利用できる。
- `pyproject.toml`: NumPy、tifffile、openpyxlは導入済み。初版のための追加依存は不要。

## 4. 画面と操作

1. `1. メンブレン選択`、`2. バンド選択` の隣に `3. 定量(Optional)` を常時表示する。
2. 第3段階を開くと、選択中の段について「定量を開始」を表示する。タブを開くだけでは解析設定を作成しない。
3. 図に採用した露光を定量用の初期候補とする。元データの利用可否を表示し、定量用露光は明示的に確定する。
4. 最初のバンドを囲むと、共通の「幅」「高さ」を設定する。既存のレーン位置を手がかりに、同サイズの枠を全レーンへ配置する。自動配置は候補であり、人が確認する。
5. 枠の内側をドラッグまたは矢印キーで上下左右に動かす。選択した枠の角・辺のハンドル、または共通サイズ欄で全枠を一括で伸縮する。幅・高さは元画像のpx単位で表示する。
6. 各レーンの近傍に、バンドROIと同サイズの背景ROIを1個配置する。背景枠の位置も個別に動かせる。初期候補をバンドの上下に置く場合も、バンドや汚れのない場所か確認する。
7. 左側にレーン別の「積分強度」「背景平均」「背景補正後」「飽和画素数」「状態」を表示する。右側で定量画像とバンド枠・背景枠を確認する。
8. 「計算」で保存し、「Excel」「CSV」から結果を出力する。ROI変更時は結果を無効にし、再計算後に出力できる。
9. ローディングコントロールの段・対応レーン・基準レーンの指定と、正規化・相対値は次版に回す。

補足の操作仕様:

- 定量しない段は未開始のままでよい。除外レーンは理由付きで残し、ゼロ値に置き換えない。
- 既存の可変レーン幅は、枠の初期中心位置だけに使う。細いレーンに合わせて1個の枠だけ縮小しない。
- 共通サイズ変更は全枠の中心を厳密に保って一括反映する。整数座標を維持するため、幅・高さはそれぞれ2px刻みで変更する。
- 隣のバンドを含む、別レーンの枠と重なる、背景枠がバンド枠と重なる場合は場所の見直しを促す。バンドと背景の重複は確定を止める。
- 画像端では枠全体の移動を制限する。枠の切り詰め、縮小、画像外のゼロ埋めはしない。サイズ変更で収まらなくなる場合はその変更を拒否する。
- 定量用露光と図用露光が違うときは両者を表示する。図用露光の変更で定量用露光を自動的に変えない。
- 第3段階を使わなくても、第2段階から図を出力できる。定量の未開始・未完了・エラーはPPTX/PNGの出力条件に加えない。

## 5. 元画像・座標・サイズの保証

### 初版は元画像のピクセル格子上で定量する

定量専用ビューには、**解析元のraw16から作った表示画像**を出す。保存するROIはraw16の座標で、軸に平行な矩形とする。左上座標 `x, y` と共通の整数 `width_px, height_px` を使い、`image[y:y+h, x:x+w]` を測定する。これで全レーンの画素数も厳密に `w × h` になる。

画面上のズームやパンは自由だが、保存座標は常に元画像の座標に戻す。半開区間と既存の外縁座標規約を使う。初版の定量ビューでは図作成用の回転補正を画素に適用せず、傾いたバンドにも同サイズの枠を配置する。傾きの大きい画像では背景が多く入るため、この制約を操作画面で分かるようにする。

既存の図上のレーン中心・段の位置を初期配置に使うのは、表示画像から解析画像までの変換が確認済みの場合だけにする。寸法比だけで座標を推測しない。対応が未確認でもraw16を直接見て枠を配置できる。

将来、傾きに沿う回転ROIを追加する場合は、角度もレーン群で共通にする。元画像に逆写像した矩形と画素の重なり面積で重み付けする方式を別途検証する。単純な多角形マスクは移動により画素数が変わるため、等面積の保証とは区別する。図用に補間済みの画像からの計算へ置き換えない。

### 定量用データの確認

`analysis.py` に定量専用の読込処理を追加する。SHA-256、寸法、ページ、単一チャネル、dtypeを検証し、元の画素値を保持する。

- 初版の対応入力は、取得値を線形に保持した16-bitグレースケールTIFF。16-bitであることや拡張子だけでは定量適性を確定しない。
- 加工の有無、書き出し方法、信号が高値／低値のどちらか、取得時の飽和上限について確認根拠を保存する。自動確認できない項目は利用者の確認として区別する。
- TIFFの表示極性や現在の `display_mapping.invert` を、そのまま信号の極性とみなさない。低値が強信号のデータを扱う場合は、確認済みの極性に従って背景との差の符号を揃える。
- 現在のSCN読み込みはメタデータ取得のみ。SCNだけの入力は初版では定量対象にせず、線形な16-bit TIFFの書き出しを案内する。
- 8-bit表示画像、色付きMerge、赤い飽和表示を焼き込んだ画像から強度を復元しない。

## 6. 計算仕様と品質表示

高値が強信号の画像では、レーン `i` の値を次で定義する。

```text
N = width_px × height_px
raw_sum[i] = バンドROI内の画素値の総和
background_mean[i] = 背景ROI内の画素値の平均
net_signal[i] = raw_sum[i] − N × background_mean[i]
```

低値が強信号と確認された画像では、`net_signal = N × background_mean − raw_sum` とする。生の総和は変更せず、極性を結果に記録する。背景補正後の負値は保持し、「背景以下」と表示する。ピクセルごと・合計後のいずれもゼロに丸めない。

任意の正規化（次版）:

```text
normalized[i] = net_signal_target[i] / net_signal_control[対応レーン]
relative[i] = normalized[i] / normalized[基準レーン]
```

現行版では、コントロールの対応付け・基準レーン・正規化値・相対値を作らない。背景補正後の信号 `net_signal` をそのまま結果表とCSVに出す。名称からコントロールを自動決定しない。次版でも、既存の `control_for_panel_ids` を候補として利用する。各段はそれぞれ全レーン共通の露光を使う。異なる標的間の補正比を絶対的なタンパク質量比と説明しない。

確定を止める条件:

- 元画像の不一致・欠落、非対応形式、読込条件や信号極性の未確認。
- 範囲外ROI、ゼロ面積、バンドと背景の重複、レーンごとのサイズ不一致。
- 比較するレーン群で定量用露光が混在している。
- 対象ROIまたは背景ROIに取得値の飽和が確認された場合、そのレーンの有効な背景補正値は出さない。測定した生値と理由は記録できる。

表示・計算上の注意:

- 飽和は元画像から判定する。16-bitの上限65535に加え、取得系の上限が分かる場合はそれを使う。根拠がない場合は「飽和上限未確認」を残し、「飽和なし」と断定しない。
- 非飽和であることは、タンパク質量に対する線形性の証明ではない。希釈系列などで確認した測定範囲の情報は別に記録する。[Bio-Rad: Data Analysis](https://www.bio-rad-antibodies.com/western-blotting-data-quantitation-normalization-densitometers-analysis-software.html)
- 飽和したレーンは生の総和・背景平均・飽和画素数を記録し、背景補正後の値と状態を「無効」にする。負の背景補正値はそのまま残す。
- コントロールまたは基準値が0以下、欠測、飽和の場合に除算しない扱いは、正規化を追加する次版で実装する。現行版は除算を行わない。
- 露光秒数で割るだけの露光間補正は行わない。飽和する場合は比較群全体で短い露光を選び直す。

## 7. 保存モデルとAPI

`Project` に、未使用時は空の `quantification_groups` を追加する。グループには次を保存する。

- `group_id`、`panel_id`、`capture_id`、`source_asset_id`、`frame_id`（座標はすべて元画像のフル解像度）。
- グループ共通の `width_px` / `height_px`、信号極性 `signal_polarity`（`high` / `low`）。
- 元画像を定量用として確認した `source_confirmed` と、取得時の飽和上限 `saturation_value`（未確認なら `null`）。
- 自動配置を行ったグループには `placement_method`（`band_selection` / `estimated` / `fallback`）と `placement_note` を記録する。旧グループには必須にしない。
- レーンごとの `lane_id`、バンドと背景の左上位置 `x` / `y` / `background_x` / `background_y`、除外状態 `excluded`。
- 計算結果 `results`（`fingerprint` と `rows`）。`rows` はレーンごとの `sample_name`、`area_px`、`raw_sum`、`background_mean`、`net_signal`、`saturated_pixels`、`status` を持つ。

幅・高さはグループだけが持つ。レーンごとに幅・高さを保存しない。既存のAnnotationの多角形が必要な箇所には、この設定から導出したものを渡す。任意のAnnotation編集を通じて共通サイズ制約を迂回できないようにする。

計算結果は生の総和、画素数、背景平均、背景補正後の値、飽和画素数、状態を保持する。正規化値・相対値は現行版では持たない。古いプロジェクトは空の設定で読めるようにし、旧版で編集された場合もfingerprintにより古い結果を検出する。

既存の `expected_revision` を使って、次の操作を追加する。

- `POST /api/start_quantification` `{panel_id, capture_id?, expected_revision}`: グループの初期化。定量用の16-bitグレースケール元画像が無い・ハッシュが一致しない場合は422。初期ROIはバンド選択の範囲・レーン境界（隙間を含む）・回転補正をraw16座標に戻して仮配置する。対応付け済みの表示画像とraw16に変換がなく、縦横比が一致する場合は寸法比で推定し、その旨を `placement_note` に表示する。範囲や対応が不明なら等間隔の仮配置と理由を返す。計算は行わない。
- `POST /api/place_quantification` `{group_id, expected_revision}`: 現在のバンド選択から再配置し、結果を消去する。既存の極性・飽和しきい値・除外状態は保持する。配置できない場合は422で、既存の枠と結果を保持する。
- `POST /api/update_quantification` `{group_id, width_px?, height_px?, signal_polarity?, source_confirmed?, saturation_value?, lanes?, expected_revision}`: 共通サイズ・極性・確認状態・飽和上限・レーン位置の更新。サイズ変更は全レーンと背景枠の中心を保ち、画像外になる変更は422。レーンごとのサイズ指定は受け付けない。いずれの変更でも `results` を消す。
- `POST /api/compute_quantification` `{group_id, expected_revision}`: 現設定の再検証、計算、結果の保存。raw16元画像を検証して計算する。手動の確認チェックは不要（`source_confirmed` は旧版互換のため保持）。背景補正は `float64` で行い、負値は保持し、飽和したレーンは `net_signal = null` にする。範囲外・バンドと背景の重複は422。
- `GET /api/quantification_info/{group_id}`: 元画像の寸法と、現在のハッシュ・設定・試料／レーン構成に対して結果が最新かを返す。
- `GET /api/quantification_source/{group_id}.png`: 定量用の元画像から作った表示専用の8-bitプレビュー。フル解像度。値の計算には使わない。
- `GET /api/quantification_csv/{group_id}`: 条件・座標・結果のCSV。結果が未計算または古い場合は422。UTF-8 BOM付きで、数式として解釈される試料名は無害化する。

入力の変更を検出した結果は「再計算が必要」とし、古い値を現在の結果として出力しない。対象は元画像のハッシュ、フレーム・撮影の対応、ROI・背景・極性・飽和上限・確認状態、試料名・レーン構成。図の文字サイズやズーム、表示用の明るさ・コントラストだけでは再計算しない。段の削除・複製・除外、レーン数の変更では対応を再確認する。配置候補の元になった図の範囲・レーン境界を変更してもROIを勝手に動かさず、対応の再確認を促す。

保存場所は既存の `.wblot`、キャッシュは `cache_dir()`、書き出しは `wblot_output/exports/` を使う。CSVは結果表と解析条件（寸法・極性・確認状態・飽和上限・元画像ハッシュ・計算式）を含み、後で同じ結果を再計算できるようにする。Excelは「定量結果」「解析条件」の2シートで出力する。正規化対応は次版で追加する。これらは利用者データであり、公開リポジトリには含めない。

## 8. 実装順序と完了条件

### 第1段階: 定量コア（現行スコープ）

- `src/wb/quantification.py` で元画素の読込、16-bitグレースケールの適性確認、ハッシュ・寸法の検証、固定ROI、背景補正、飽和・除外の判定を実装する。
- `src/wb/model.py` にグループとレーンの型を追加する。
- 合成TIFFで、理論値・原点・画素数・整数オーバーフロー・負値・飽和判定を検証する。
- APIの統合テストは `tests/test_quantification_api.py` に置き、合成画像だけでHTTP経由の契約を確認する。

### 第2段階: 保存・API・再計算（現行スコープ）

- `api.py`、`app.py` に `start_quantification` / `update_quantification` / `compute_quantification` と、情報・プレビュー・CSVの取得を追加する。
- 保存・再読込、未開始の旧プロジェクト、更新競合、元画像ハッシュの変更、設定・試料名・レーン構成の変更による結果の無効化を検証する。
- `readiness.py` の図出力条件と、定量の利用可否判定を分離する。定量の未開始・未完了・エラーを、図のPPTX/PNG出力条件に加えない。

### 第3段階: 第3タブとROI操作（現行スコープ）

- `App.svelte` に `3. 定量(Optional)` を常時表示する。
- 定量専用のパネルと、共通サイズ・移動用の小さなJSモジュールを追加する。既存の `request(operation, payload)` と座標変換を再利用する。
- 異なるレーン幅、上下にずれたバンド、ドラッグ、キー操作、ズーム、画像端、サイズ一括変更を合成画像で検証する。
- 定量を開始せず図を作れること、定量用露光と図用露光を区別できることを確認する。

### 第4段階: 正規化・出力・配布確認（次版）

- コントロールの明示的なレーン対応、基準レーン、正規化値・相対値を追加する。
- 欠測、0以下の分母、飽和、コントロール変更後の再計算を検証する。
- CLI操作も同じAPIへ接続する。操作説明を追加する場合は2か所の `skills/wblot/SKILL.md` を同期する。
- `uv run pytest`、フロントエンドの `npm test` と `npm run build` を実行し、ビルド済み `dist/` を更新する。macOS・Windowsで確認する。
- 公開前に `uv run python dev/check_public.py` と `uv run python dev/check_public.py --since origin/main` を実行する。テスト・説明・確認用画像は合成データと架空名のみを使う。

現行スコープの完了条件は、**定量を使わない既存フローを維持したまま、同じ幅・高さのROIをレーンごとに平行移動して元画像から計算でき、その条件と結果を保存・再現・CSV出力できること**。ローディングコントロールによる正規化は次版の完了条件に含める。


## コマンド操作

`wbm quantify start <段> [--capture <撮影ID>]` はWebUIと同じ自動配置を行う。`show [<group_id>]`、`place <group_id>`、`update <group_id> --settings <JSONファイル>`、`compute <group_id>`、`export <group_id> --format excel|csv` を使う。全操作で `--project` と `--json` を利用できる。更新のJSONレシートは `ok`・`project_revision`・対象の `group` を返し、プロジェクト全体は返さない。画素値は再サンプリングせず、共通サイズの整数座標ROIで定量する。自動配置の背景枠はバンドROIとの重なりを避けた候補であり、背景に適切かどうかは元画像上で調整する。
